# EC機能追加：概要・開発方針

## 目的

既存のLaravel製タロットアプリに、実物商品を販売するEC機能を追加するための事前調査と実装前設計をまとめる。商品・注文・決済・在庫・配送をタロット占いの主要処理から分離し、既存の認証と管理者権限は適切な範囲で再利用する。

この文書は設計案であり、未確定事項は「要決定」と明記する。決済事業者、配送条件、税、返品条件等を確定したものとして扱わない。

## 調査で確認した前提

- リポジトリはREADME上、単独で動作するレガシーアプリのコピーとして説明されている。外部の本番システムや共有DBとの接続は確認していない。
- `composer.json` は `laravel/framework` `^13.17`、PHP `^8.3` を要求し、確認時の実行環境はLaravel 13.33.0、PHP 8.4.25。
- `config/database.php` の既定接続はSQLiteで、MySQL接続設定も定義されている。稼働DBの種類・適用済みmigrationは、作業制限に従い接続せず、migration定義のみから調査した。
- Blade、Vite、Tailwind CSS v4を使用。AI占いにはOpenAI Laravel連携、Stripe PHP SDKも依存関係に存在する。
- 現在のStripe処理は占いクレジット購入基盤で、Webhook署名検証・イベント記録がある一方、`StripeBillingService` のEC決済処理は未実装のプレースホルダーである。

## 基本方針

1. **既存機能を保護する**：占いの生成、保存、ゲストセッション、公開共有、クレジット、Stripeクレジット購入を回帰テストする。ECの失敗が占い処理を止めないこと。
2. **責務を分ける**：EC用のルート、コントローラー、サービス、画面、モデル、テーブルを独立させる。タロット連携は任意の推薦表示に限定し、占い結果データをECの都合で書き換えない。
3. **既存スキーマの変更を絞る**：既存ユーザーや占いテーブルへの広範な列追加を避ける。占い推薦の永続化は専用の関連テーブルを候補とし、タロット結果自体への影響を局所化する。
4. **注文時点の事実を保存する**：商品名、SKU、単価、数量、税・送料を注文明細にスナップショットとして残す。注文履歴を現在の商品価格や商品削除に依存させない。
5. **決済プロバイダーを抽象化する**：カード番号等は自社DBに保存しない。決済セッション生成、Webhook検証、結果の正規化をプロバイダー境界に閉じ込める。
6. **在庫を原子的に扱う**：注文確定時にDBトランザクションと行ロックまたは条件付き減算で在庫を予約し、決済成功で販売確定、失敗・期限切れで一度だけ予約を解放する。
7. **削除よりアーカイブを優先する**：注文・占い推薦・在庫履歴から参照される商品は物理削除せず、販売停止・アーカイブにする。
8. **公開前に商取引表示を更新する**：既存の特定商取引法表示は現状、商品販売の公開内容ではない。販売者表示、送料、支払・引渡時期、返品条件、個人情報の利用目的等を確認・更新する。

## 事業側の回答（2026-11-05）

- 決済はStripeを採用し、返金は初期段階で全額返金を対象とする。
- 販売地域は日本と指定した海外地域。具体的な国は後日設定し、未設定の国は購入不可にする。**（2026-11-07変更）初期リリースは日本国内のみとし、海外配送は行わない。**
- 表示/決済通貨はJPY。商品価格は税込として扱う方針だが、国別税率・徴収義務の専門家確認は未了であり、チェックアウト公開前のブロッカーとする。
- 税額は税込商品明細ごとに逆算し、1円未満を四捨五入する。送料の課税有無は国別設定に従う。
- 初期運用は商品ごとにSKU/価格/在庫1つ。DBは将来の複数variantを妨げない形にする。
- 送料は国/地域ごとの固定料金テーブルとし、対象地域と料金は後日設定。
- 在庫予約期限は決済開始から30分。
- ログインユーザーには本人の注文履歴を提供する。ゲスト購入者には期限付き照会リンクを用意する。
- 返金はStripe API経由。返品後の在庫復元は、返品受領・検品後に別途行う方針。

## 対象範囲

商品・カテゴリ・画像・価格/SKU・在庫・販売状態の管理、商品検索・詳細、カート、ゲスト購入、注文確認、外部決済、注文完了メール、管理者向け注文・決済・配送管理、在庫変動履歴、送料、占い結果への商品1件の推薦表示を対象候補とする。

税計算、クーポン、返品・返金運用、複数倉庫、配送会社API、会員向け住所帳、領収書、商品レビューは要件として未確定であり、初期リリースに含めるかを決める。

## 公開前ゲート

ユーザー承認に基づき実装を進めている。アプリケーションのコードとmigration定義は追加済みだが、永続DBへのmigration適用や本番接続は行っていない。販売開始前に、未設定の配送国・送料、専門家確認済みの税率・徴収義務、Stripe本番Webhook、メール/Queue運用、保存期間・法務表示を確定する。Stripe Checkout期限との安全余裕として予約は30分30秒になっているため、30分を厳密な期限とするかも確認する。
